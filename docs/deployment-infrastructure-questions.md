# Deployment Infrastructure Questions

Use these questions when talking to the person who will approve the website launch, even if they are not technical.

Keep the conversation focused on decisions, not code.

## Domain

1. What is the exact website address we want to keep using for the public site?
2. Do we want to use `orienda.com`, `www.orienda.com`, or both?
3. Who is the current owner of the domain?
4. Which company or person currently manages the domain account?
5. Which registrar is the domain using now?
6. Who has login access to that domain account today?

## Domain Transfer Or Domain Access

7. Do you want to fully transfer the domain to our account, or keep it in the current account and only give us access?
8. If you want to transfer it, who can approve the transfer?
9. If you want to transfer it, who can unlock the domain?
10. If you want to transfer it, who can provide the transfer code or authorization code?
11. Which email address currently receives domain transfer approval emails?
12. Who can confirm that this email inbox is accessible?
13. If you do not want to transfer the domain, can you give us DNS access instead?
14. If DNS access is given instead of transfer, who will make the DNS changes for us?
15. Is there any internal approval needed before changing domain ownership or DNS settings?
16. Is there any risk that the current domain account could be lost, closed, or become inaccessible later?

## Hosting

17. Where do we want the website to be hosted?
18. Do we already have a hosting account?
19. If yes, whose account is it under?
20. Who should have access to the hosting account?
21. Do we want a low-cost launch first, or a more permanent setup from the beginning?
22. If the website goes down, who should be contacted first?

## DNS

23. Who manages the DNS settings for the domain today?
24. Do we already use Cloudflare or another DNS provider?
25. Who has login access to the DNS provider?
26. Are we allowed to change the website records when launch day comes?
27. If DNS needs to be updated, who must approve the change?

## IP And Server Details

28. Do we already have a server or hosting destination for the website?
29. If yes, do we already know the IP address or hosting target?
30. Who can provide the server details if needed?
31. If we need to point the domain to a server or platform, who can do that?

## SSL And Security

32. Do we want the website to open with secure `https` from day one?
33. Who is responsible for approving the security setup for the public website?
34. Do we need any restrictions on who can log in to the admin area?
35. Do we want the admin area hidden from public users as much as possible?

## Email And Ownership

36. Which email address should be used for domain and hosting ownership going forward?
37. Should the domain and hosting belong to one person, or to the hospital/company?
38. Who should be the long-term owner of the website accounts?
39. If the current account owner leaves, who should still have access?

## Launch Control

40. Who gives final approval to connect the domain to the live website?
41. On launch day, who will be available to confirm the website is working?
42. Do we want a test version first before the real domain is connected?
43. If something goes wrong after launch, who decides whether to keep the site live or temporarily take it down?

## Useful Final Questions

44. Do we already have everything needed to use the existing domain for the new website?
45. If not, what is still missing: domain transfer approval, registrar access, DNS access, hosting access, or final approval?
46. Which person can give us the missing access fastest?
